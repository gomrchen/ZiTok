## 🌿 分支命名规范

### 主要分支
- `main` - 主分支，始终保持可发布状态
- `develop` - 开发分支，集成最新开发功能

### 功能分支
```
feature/功能描述
feature/用户模块
feature/音频播放
feature/社交功能
```

### 修复分支
```
fix/问题描述
fix/登录异常
fix/音频卡顿
fix/内存泄漏
```

### 热修复分支
```
hotfix/紧急修复描述
hotfix/生产环境崩溃
hotfix/安全漏洞修复
```

### 发布分支
```
release/版本号
release/v1.0.0
release/v1.1.0
```

## 📝 提交消息规范

### 格式
```
<类型>(<范围>): <描述>

[可选的正文]

[可选的脚注]
```

### 类型说明
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码格式调整（不影响功能）
- `refactor`: 代码重构
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建过程或辅助工具的变动
- `ci`: CI/CD 相关
- `build`: 构建系统或外部依赖的变动

### 范围说明
- `frontend`: 前端相关
- `backend`: 后端相关
- `api`: API接口
- `ui`: 用户界面
- `auth`: 认证授权
- `audio`: 音频功能
- `social`: 社交功能
- `config`: 配置文件

### 提交消息示例
```bash
# 好的提交消息
feat(frontend): 添加用户登录界面
fix(backend): 修复音频上传接口异常
docs: 更新API文档
refactor(audio): 重构音频播放器组件

# 不好的提交消息
update code
fix bug
add feature
```

### 详细提交消息示例
```
feat(auth): 实现JWT用户认证系统

- 添加用户注册和登录接口
- 实现JWT token生成和验证
- 添加用户权限中间件
- 更新用户模型和数据库迁移

Closes #123
```

## 🔄 分支工作流程

### 1. 功能开发流程
```bash
# 1. 从develop分支创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/用户模块

# 2. 开发功能并提交
git add .
git commit -m "feat(frontend): 添加用户注册界面"

# 3. 推送到远程
git push origin feature/用户模块

# 4. 创建Pull Request到develop分支
# 5. 代码审查通过后合并
# 6. 删除功能分支
git branch -d feature/用户模块
```

### 2. 修复流程
```bash
# 从对应分支创建修复分支
git checkout develop  # 或 main（紧急修复）
git checkout -b fix/登录异常

# 修复并提交
git commit -m "fix(auth): 修复用户登录验证逻辑错误"

# 推送并创建PR
git push origin fix/登录异常
```

### 3. 发布流程
```bash
# 从develop创建发布分支
git checkout develop
git checkout -b release/v1.0.0

# 版本准备工作（更新版本号、文档等）
git commit -m "chore: 准备v1.0.0版本发布"

# 合并到main和develop
git checkout main
git merge release/v1.0.0
git tag v1.0.0

git checkout develop
git merge release/v1.0.0
```

## 👥 代码审查规范

### Pull Request 要求
1. **标题清晰**: 使用规范的提交消息格式
2. **描述详细**: 说明变更内容、原因和影响
3. **关联Issue**: 使用 `Closes #123` 关联相关问题
4. **测试覆盖**: 确保新功能有对应测试
5. **文档更新**: 如有必要，更新相关文档

### PR模板
```markdown
## 变更类型
- [ ] 新功能
- [ ] Bug修复
- [ ] 文档更新
- [ ] 代码重构
- [ ] 性能优化

## 变更描述
简要描述本次变更的内容和原因

## 测试说明
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试完成

## 相关Issue
Closes #123

## 截图（如适用）
添加相关截图或GIF

## 检查清单
- [ ] 代码符合项目规范
- [ ] 已添加必要的测试
- [ ] 文档已更新
- [ ] 无破坏性变更
```

### 审查要点
- 代码质量和可读性
- 功能正确性
- 性能影响
- 安全性考虑
- 测试覆盖率
- 文档完整性

## 🚀 发布流程

### 版本号规范
使用语义化版本控制 (SemVer)：`主版本.次版本.修订版本`

- **主版本**: 不兼容的API修改
- **次版本**: 向下兼容的功能性新增
- **修订版本**: 向下兼容的问题修正

### 发布检查清单
- [ ] 所有测试通过
- [ ] 代码审查完成
- [ ] 文档更新完整
- [ ] 版本号正确更新
- [ ] 变更日志已更新
- [ ] 生产环境部署测试

## 🛠️ 工具配置

### Git Hooks
建议配置以下Git hooks：

```bash
# pre-commit: 提交前检查
#!/bin/sh
npm run lint
npm run test

# commit-msg: 检查提交消息格式
#!/bin/sh
npx commitlint --edit $1
```

### 推荐工具
- **Commitizen**: 交互式提交消息生成
- **Commitlint**: 提交消息格式检查
- **Husky**: Git hooks管理
- **Conventional Changelog**: 自动生成变更日志
